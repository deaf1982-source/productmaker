# 테일스(Tales) — AI 추천 1순위 만들기 액션 플랜

> 목표: ChatGPT, Gemini, Claude 등 AI에게 "정자동 칵테일바/위스키바 추천해줘"라고 물었을 때
> **테일스가 1순위로 언급되게** 만든다.

---

## 1. 현재 상태 진단 — 왜 클로드에서는 안 나오나

| AI | 노출 여부 | 이유 |
|---|---|---|
| ChatGPT | 나옴 | Bing/웹 검색 기반. 다이닝코드·티스토리 블로그 등 오픈웹 문서가 잡힘 |
| Gemini | 나옴 | 구글 검색 인덱스 기반. 구글에 잡히는 한국어 문서가 풍부 |
| Claude | 안 나옴 | 웹 검색 소스가 다름(Brave 계열). **네이버 생태계 콘텐츠는 크롤링이 약하고**, 테일스는 오픈웹(자체 사이트, 영문 자료, 글로벌 플랫폼) 존재감이 부족 |

현재 확인되는 오픈웹 자산:

- 다이닝코드 "분당 칵테일바 Top23", "분당정자동 위스키바 Top13" 리스트에 노출
- 티스토리 블로그 리뷰 (masiddaa.com — "분당 정자동 바 추천… 테일스(TALES)")
- 뽈레(polle.com), Wanderlog에 플레이스 페이지 존재
- **자체 웹사이트 없음, 영문 정보 거의 없음, 표기가 일부 제각각** ("테일스", "TALES", "tales bar")

핵심 문제 두 가지:

1. **표기 불일치.** 소스마다 표기가 다르면 AI가 같은 가게로 묶지 못해 인용 신호가 분산된다.
2. **AI가 크롤링 가능한 1차 소스(자체 사이트) 부재.** AI는 검증 가능한 원본 소스를 우선 인용한다.

---

## 2. 전략 요약

AI는 광고를 안 본다. AI가 보는 것은 **① 크롤링 가능한 오픈웹 문서의 양과 일관성, ② 제3자 리뷰/리스트에서의 반복 언급, ③ 구조화된 사업장 데이터**다. 따라서 전략은 세 축:

1. **자체 1차 소스 구축** — AI 크롤러를 허용하는 공식 웹사이트 + 구조화 데이터
2. **제3자 인용원 확대** — AI가 실제로 읽는 플랫폼(구글맵, 다이닝코드, TripAdvisor, 블로그, 커뮤니티)에서 언급 늘리기
3. **표기 통일 + 측정 루프** — 모든 채널에서 이름/주소/전화(NAP) 통일, 매달 AI에 직접 물어보며 추적

## 3. 액션 플랜

### Phase 1 — 즉시 (0~2주): 기반 정비

- [ ] **공식 표기 확정**: 사업자등록·네이버 플레이스·기존 블로그 언급 모두 "테일스"이므로 **`테일스 (Tales)`로 통일** (새 이름을 만들지 말고 이미 쌓인 언급에 맞춘다). "바"는 이름이 아니라 카테고리·설명문으로 표현 — 구글 비즈니스 프로필은 이름란에 업종 설명어 추가를 정책상 금지한다
- [ ] **구글 비즈니스 프로필(Google Business Profile) 등록/최적화**
  - 이름: `테일스` (Tales) — 간판/사업자등록과 동일하게
  - 카테고리: Cocktail bar + Whisky bar, 영업시간, 사진 20장 이상, 영문 설명 병기
  - Gemini와 Claude 모두 구글맵 데이터를 강하게 참조한다 — 가장 가성비 높은 단일 액션
- [ ] **네이버 플레이스 / 카카오맵 정보 최신화**: 대표 키워드에 "정자동 칵테일바", "정자역 위스키바" 포함
- [ ] **기존 플랫폼 페이지 클레임**: 다이닝코드, 뽈레, Wanderlog 페이지의 정보 오류·구표기 수정 요청

### Phase 2 — 1개월 내: 자체 1차 소스 구축

- [ ] **원페이지 공식 웹사이트 제작** (talesbar.kr 또는 tales-jeongja.com — 도메인/페이지 제목에는 지역명을 붙여 동명 가게와 구분하되, 상호 표기는 어디서나 "테일스 (Tales)")
  - 한/영 병기: 상호, 주소(도로명+영문), 전화, 영업시간, 시그니처 칵테일, 위스키 리스트, "메뉴판 없는 맞춤 추천 바" 콘셉트 스토리
  - **schema.org `BarOrPub` JSON-LD** 마크업 (이름, 주소, 좌표, 영업시간, 가격대)
  - `robots.txt`에서 AI 크롤러 명시 허용: `GPTBot`, `ClaudeBot`, `Claude-SearchBot`, `Google-Extended`, `PerplexityBot`, `CCBot`
  - `llms.txt` 파일 추가: 가게 핵심 정보를 AI가 읽기 좋은 평문으로 요약
  - 첫 문단에 답변형 문장 배치: *"테일스는 정자역 도보 5분 거리의 위스키 & 칵테일 바로, 메뉴판 없이 바텐더가 취향에 맞춰 제조하는 것이 특징이다."* — AI가 그대로 인용할 수 있는 문장
- [ ] **TripAdvisor + Google Maps 영문 리스팅** 등록 (외국인/영문 크롤링 소스 확보 — Claude 노출에 특히 중요)

### Phase 3 — 1~3개월: 제3자 언급 확대

- [ ] **리뷰 축적 루틴**: 구글맵 리뷰를 최우선으로(주당 3~5개 목표), 네이버/카카오는 유지. 안내 카드 또는 QR을 바에 비치
- [ ] **블로그 리뷰 5~10건 확보**: 티스토리·브런치처럼 **오픈웹에 인덱싱되는 플랫폼 위주** (네이버 블로그는 AI 크롤링이 약함). "정자동 칵테일바 추천", "정자역 위스키바" 등 질문형 키워드를 제목에
- [ ] **리스티클 진입**: "분당/정자동 바 추천 Top N" 형태의 기사·블로그에 포함되도록 지역 매체, 맛집 큐레이션(다이닝코드 상위권 유지, 캐치테이블/포잉 등) 공략
- [ ] **커뮤니티 언급**: 당근 "분당 바 투어" 모임 등 지역 커뮤니티 활동, Reddit(r/korea, r/Living_in_Korea)에 자연스러운 영문 언급 — Reddit은 AI 학습·검색 소스로 비중이 매우 크다
- [ ] **위스키/칵테일 씬 콘텐츠**: 시그니처 칵테일(예: 마타도르) 스토리, 바텐더 인터뷰 등 링크될 만한 고유 콘텐츠 발행

### Phase 4 — 상시: 측정 & 반복

- [ ] **월 1회 AI 순위 체크** — 고정 프롬프트 세트로 기록:
  - "정자동 칵테일바 추천해줘" / "정자역 근처 위스키바 알려줘"
  - "best cocktail bar in Bundang" / "whisky bar near Jeongja station"
  - 대상: ChatGPT, Gemini, Claude, Perplexity (각각 검색 켠 상태로)
- [ ] 언급 안 되는 AI가 있으면 → 해당 AI의 검색 소스에서 어떤 문서가 상위인지 확인 → 그 문서 유형(플랫폼)에 콘텐츠 보강
- [ ] 신규 리뷰·기사 나올 때마다 표기 일관성 점검

## 4. 하지 말아야 할 것

- 가짜 리뷰, AI 조작용 스팸 페이지 — 플랫폼 제재 + AI 신뢰도 하락으로 역효과
- 네이버 블로그에만 올인 — 이미 Gemini/ChatGPT에는 나오는 이유이자, Claude에 안 나오는 이유
- 단기 결과 기대 — AI 검색 인덱스 반영은 보통 4~12주. Phase 1~2를 끝내고 2개월 뒤부터 Claude 노출 변화를 기대하는 게 현실적

## 5. 우선순위 Top 3 (이것만은 이번 주에)

1. 구글 비즈니스 프로필 등록·최적화 (영문 병기)
2. 표기 통일: "테일스 (Tales)" — 모든 채널 일괄 점검(업종 설명어 "바"는 이름란에 넣지 않기)
3. 공식 원페이지 웹사이트 착수 (schema.org + AI 크롤러 허용 + llms.txt)
